# מסירת MVP מקומי — נתיב

תאריך: 2026-08-28

## מה קיים ועובד

המערכת רצה כאפליקציית React נפרדת בעברית וב־RTL מול Firebase Emulator בלבד.
כל הקריאות העסקיות עוברות דרך Callable Functions; כללי Firestore חוסמים גישה
ישירה מהלקוח. נתוני ההדגמה אנונימיים ואינם נלקחים מ־EdTrack.

זרימת תלמיד: כניסה, בחירת קורסים בכל מקבץ, מניעת דירוג כפול, נימוק אופציונלי,
שמירת טיוטה אוטומטית, הגשה בגרסה, צפייה בשיבוץ, הגשת ערעור ומעקב.

זרימת רכז: סגירת בחירה, יצירת אצוות AI מקומית פעם אחת, בדיקת פלט גולמי,
עריכת עותק מאושר עם סיבה, מעבר לשיבוץ, הרצת מנוע דטרמיניסטי, אישור גרסה,
פרסום נפרד, פתיחת ערעורים, ניתוח השפעה, החלטה וביצוע מפורש.

זרימת ערעור: המסך מציג את הדירוגים והנימוק במקבץ, את צילום הטופס המלא,
קורס לפני ואחרי, קיבולת, כפילות, אילוצים, צורך בהעברת תלמיד ורשימות מושפעות.
אישור הערעור יוצר `approved_pending_execution` ואינו משנה שיבוץ. הביצוע דורש
גרסת workflow עדכנית, מריץ ניתוח מחדש ורק אז משנה את התוצאה ויוצר הודעות.

זרימת הרשאות: מנהל גישה יכול להקצות כמה תפקידים לכמה משתמשים. תפקידי המערכת
מתורגמים ליכולות שרת. מנהל גישה ללא תפקיד מקצועי נחסם מ־`getWorkflow` ואינו
מקבל נימוקים, שיבוצים או ערעורים.

## מנוע השיבוץ

המנוע ב־`src/domain/assignmentEngine.ts` שומר את עקרונות המימוש ההיסטורי:

- seed קבוע 42 ותוצאה ניתנת לשחזור;
- אילוצי חובה ואיסור לפני חלוקה רגילה;
- מגישים לפני מי שלא הגיש;
- מעבר לפי דירוג, תחילה עד יעד ואחר כך עד מקסימום;
- פלט AI מאושר משמש רק כשובר שוויון;
- השלמה לפי הפער הגדול ביותר ליעד;
- בדיקת מדיניות חזרה וקיבולת לכל קורס.

ב-MVP אין העברה אוטומטית של תלמיד נוסף ואין עקיפה אוטומטית של קיבולת. חריגה
נחסמת ומוחזרת למסלול בדיקה. מסלול אישור שני ורשימת המתנה מלאה הם הרחבות לפני
פיילוט אמיתי.

## AI ופרטיות

הספק הנוכחי הוא mock מקומי ואינו שולח מידע לרשת. לפני ההערכה מוסרים דוא״ל
וטלפון מהנימוק. הקלט הסמנטי אינו כולל שם, כיתה, דוא״ל או מזהה תלמיד; המיפוי
בין מזהה אנונימי לתלמיד נשמר ברשומת השרת בלבד. היעדר נימוק מפיק `neutral`.
חיבור Gemini יבוצע בפרויקט Google Cloud נפרד של נתיב ורק לאחר הגדרת Secret,
מדיניות שמירה וחוזה פלט מאושר.

## בדיקות

- `pnpm check`: lint, TypeScript ללקוח ולשרת, 32 בדיקות יחידה ובניית production.
- `pnpm test:emulator`: בדיקות מתאם Firestore וכללים חסומים.
- `pnpm test:system`: ארבע בדיקות מערכת דרך Auth, Functions ו־Firestore.
- בדיקת המערכת מכסה בחירה והגשה, הרשאות, AI, שיבוץ, אישור, פרסום, ערעור,
  ניתוח, החלטה ללא שינוי, ביצוע שינוי ודיווח למזכירות.

## הפעלה

```powershell
pnpm install
pnpm emulators
```

האפליקציה: `http://127.0.0.1:5000`

## מצב דרישות הענן

1. הושלם: Hosting,‏ Functions codebase ומסד Firestore נפרדים בתוך `edtrack-development`, עם Firebase Auth משותף.
2. הושלם חלקית: ארגון, חברות ומנוי `nativ` נקראים מ־EdTrack; מסלול יבוא כיתות ותלמידים למחזור טרם הושלם.
3. הושלם: כניסה ארגונית והקצאות תפקיד מוצר מתועדות במסד `nativ`; חשבונות ההדגמה נשארו באמולטור בלבד.
4. חיבור Gemini ייעודי, בדיקות אנונימיזציה מורחבות וניטור עלויות/כשלים.
5. מומש תור SMTP עם חוזה תוכן מאושר, בדיקת נמענים וקבלות מסירה. ראו `docs/mail-delivery-2026-09-03.md`; רשומות `queued_mock` ישנות אינן נשלחות.
6. השלמת רשימת המתנה, אישור שני לחריגת מקסימום, יצוא ודוחות מסכמים.
7. בדיקות קבלה על צילום נתונים אנונימי והרצה מקבילה מול המנוע הקיים.
8. הושלם חלקית: Rules, Secrets ומדיניות מחיקה נבדקו; App Check ממתין לרישום האתר ולניטור לפני אכיפה.
9. הושלם: claims של ההדגמה הוחלפו בענן בהרשאות מוצר שרתיות ובבדיקת מנוי בכל callable.

דוח הפריסה המדויק נמצא ב־`docs/cloud-deployment-2026-08-29.md`.
