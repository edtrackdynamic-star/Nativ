# ייבוא תיאורי קורסים ממסמך

## מטרת המהלך

רכז שיבוץ יכול לצרף למחזור מסמך תכנים קיים, לזהות ממנו שמות קורסים, מורים ותיאורים, ולבחור אילו תיאורים להחיל על טיוטת הקטלוג. התהליך מסייע בהזנה ואינו מחליף את הבדיקה והעריכה של הרכז.

## זרימת העבודה

1. הרכז מזין קישור ל-Google Docs או בוחר קובץ Word מסוג `.docx` בגודל של עד 4MB.
2. רק לאחר לחיצה על "זיהוי תיאורי קורסים" תוכן המסמך נשלח ל-Gemini.
3. Gemini מחזיר הצעות הכוללות שם קורס, שם מורה, תיאור והתאמה אפשרית לקורס קיים.
4. הרכז בודק את ההתאמות, משנה יעד ותיאור לפי הצורך ומאשר במפורש החלפה של תיאור קיים.
5. לחיצה על "החלת התיאורים שסומנו" מעדכנת את טיוטת הקטלוג בלבד. שמירת המחזור נשארת פעולה נפרדת של הרכז.

קובץ Word והתוכן שחולץ ממנו אינם נשמרים במערכת. הטקסט שנשלח מוגבל ל-120,000 תווים. מסמך Google פרטי צריך להיות משותף לקריאה עם חשבון השירות `369491378125-compute@developer.gserviceaccount.com`.

## הרשאות וחשיפה לתלמיד

- פעולת החילוץ זמינה רק לבעל הרשאת `nativ.assignment.manage` ונרשמת בצד השרת באמצעות המפתח הסודי הקיים של Gemini.
- המסמך מטופל כמקור בלתי מהימן; הוראות שמופיעות בתוכו אינן מבוצעות.
- קישור המסמך מוצג לתלמיד רק אם הרכז הפעיל את האפשרות המתאימה. כשהאפשרות כבויה, השרת מסיר את הקישור גם מתשובת הרשת לתלמיד.
- התלמיד רואה רק את התוכן שנשמר בקטלוג. לאחר פרסום שיבוץ הוא יכול לפתוח את תיאור הקורס שאליו שובץ ולראות את שמות המורים.

## פריסה ואימות

השינוי דורש את פונקציות `extractCourseDescriptions`, `saveCycleCatalog` ו-`getChoiceContext`, את Hosting של נתיב ואת הפעלת Google Drive API בפרויקט הענן. אין שינוי ב-Rules או בנתונים חיים.

האימות כולל בדיקות יחידה לחוזה הפלט של Gemini ולתצורת הטופס, בדיקות מערכת להרשאת החילוץ ולסינון קישור מוסתר, בדיקת בנייה ובדיקת ממשק שבה אין החלה אוטומטית ותיאור קיים מוגן מהחלפה לא מכוונת.
